01 · Identity

Site Name

Pokémon Team Guide

I selected this name because it immediately identifies both the topic and the site's main benefit: helping visitors learn about Pokémon and plan a team. “Team Guide” communicates an educational, beginner-friendly approach rather than a collection of unrelated facts.

The visual identity will use a simple circular emblem inspired by the idea of collecting Pokémon, with the same navy and red colors used throughout the site.

Project location: The final website will be developed in the final subfolder of my wdd231 repository and published through GitHub Pages.

02 · Content & scope

Site Purpose

Pokémon Team Guide will help Pokémon fans discover Pokémon, understand their types and base statistics, and organize ideas for a balanced team. Visitors will be able to explore a searchable catalog, view detailed information, save favorites, and read simple team-building advice.

Target audience: New and casual Pokémon players who want clear information and practical team ideas, as well as fans who enjoy comparing their favorite Pokémon. The website's content and navigation will be in English.

Three Main Pages

Home

index.html

An introduction, links to the explorer and team guide, featured Pokémon, and quick tips that explain type variety and team roles.

Pokémon Explorer

explorer.html

A catalog with name search, type filters, base statistics, favorite controls, and a details dialog for each Pokémon.

Team Guide

teams.html

Team examples, explanations of useful roles, saved favorites, and a form for submitting a visitor's team idea.

Planned Features

How the final website will support its purpose
FeaturePlanned Implementation
Pokémon catalogLoad a curated local JSON file with the Fetch API and async/await. Render at least 15 Pokémon, each with a name, Pokédex number, type or types, HP, Attack, and Speed. Include a helpful error message with try...catch.
Search and filtersRespond to text input and type selection. Use array methods such as filter() and map(), template literals, and DOM updates to display matching entries and a result count.
Details and favoritesUse an accessible dialog for additional statistics and team-role notes. Save selected Pokémon in localStorage so visitors can return to their favorites.
Team idea formProvide labeled fields for a visitor's name, email, team name, experience level, and preferred Pokémon. Submit the data to thankyou.html, which will display the submitted values. This confirmation page supports the three main pages.
Structure and creditsOrganize JavaScript with ES modules. Use consistent navigation, a favicon, meaningful metadata, and a footer with author information, an attributions page, and the final demonstration video link.

Data and images: The curated dataset will be based on PokéAPI information, with Pokémon artwork and external content credited on an attributions page. Images will be optimized, given descriptive alternative text, and loaded lazily when below the initial viewport.

Scope: Team advice will explain type variety and general roles. Recommendations will identify their game context when applicable, since available Pokémon and battle rules can differ between games.

03 · Visitor questions

Scenarios

These questions represent the needs of the target audience and will guide the website's content and features.

  1. What types and base statistics does a Pokémon have, and how can I compare it with other Pokémon?

    The explorer will show consistent data fields and offer a details dialog so visitors can inspect Pokémon using the same information.

  2. How can I build a team with different types and useful roles instead of choosing only my favorites?

    The Team Guide page will provide examples and explain how type variety, offense, defense, and speed contribute to team balance.

  3. How can I find Pokémon of a particular type without browsing the entire catalog?

    Visitors will use name search and a type filter to narrow the catalog and see how many entries match.

  4. Can I save the Pokémon I like and return to them later?

    Favorite controls will store selections locally and make them available on the Team Guide page during future visits in the same browser.

04 · Visual identity

Color Scheme

The palette combines a strong navy base, a red accent associated with Pokémon collecting, and light surfaces that keep the information easy to read. This plan uses the same palette intended for the final website.

Selected colors and their uses
ColorHex ValueWhere It Will Be Used
Navy#16324FHeader and footer backgrounds, headings, body text, navigation, and borders.
Deep Red#B4232BLinks, section numbers, focus indicators, logo accents, and primary action buttons.
Warm Cream#FFF8EFPage background, feature cards, callouts, and alternate table rows.
White#FFFFFFMain content surfaces and text on navy headers or red buttons.

Contrast: Navy text on white is approximately 13.1:1; deep red text on white is 6.5:1; deep red text on cream is 6.2:1. These combinations exceed the 4.5:1 target for normal text. Links will also be underlined, and focus indicators will remain visible.

Wireframe convention: The required sketches use black (#000000) and white (#FFFFFF) to communicate structure. Black is reserved for those diagrams.

05 · Type system

Typography

The website will use two system fonts. This combination provides a distinctive heading style and readable body text while avoiding additional font downloads.

Georgia · Headings

Build a balanced team

Georgia will be used for the main page heading, section headings, and card titles. Bold headings will establish a clear hierarchy.

Arial · Body & interface

Explore Pokémon types, compare their statistics, and save your favorites for your next team.

Arial will be used for paragraphs, navigation, buttons, form labels, tables, and statistics. Body text will start at 16 pixels with generous line spacing.

The CSS font stacks will be Georgia, serif and Arial, sans-serif. Headings will scale with the viewport, and visitors will be able to zoom without losing content.

06 · Home page structure

Wireframes

These black-and-white raster sketches outline the home page's structure. Crossed boxes mark image areas; labeled rectangles identify content, navigation, and actions. The two views show how the same content adapts to different screen sizes.

Small Viewport: Mobile

At small widths, the logo and menu control appear at the top. The menu button expands the navigation links. Hero content, action links, featured Pokémon, and team tips follow a single-column flow with comfortable touch targets.

Large Viewport: Desktop / Tablet

At larger widths, the navigation links appear horizontally. The hero introduction and illustration sit side by side, followed by three featured Pokémon cards and a row of team tips. Tablet widths will reduce the number of columns as needed.

Responsive behavior: The final website will use CSS Grid and Flexbox, flexible image sizes, and a navigation breakpoint around 720 pixels. Layouts will be checked at 320, 375, 768, and 1440 pixels to prevent horizontal scrolling.

Development reference

Quality & Sources

During development, I will validate HTML, check accessibility and keyboard navigation, verify color contrast, and run Lighthouse in mobile and desktop modes. The final site will use semantic landmarks, labeled controls, meaningful alternative text, optimized images, and a target transfer size under 500 kB per page.
